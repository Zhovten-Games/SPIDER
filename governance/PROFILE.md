# Учредительный профиль SPIDER

Редакция `spider-profile-0.1.0-candidate`. Локальная адаптация Конституции кода
FOP-Oksana-Dubinetska/code-constitution, commit
`220dc9c286ae06f8b6ed60cdda75112eed0408ed`. CC BY-SA 4.0.

Публикация профиля и установка проверок исполняют запрос автора на подготовку
основы. Формальная ратификация этой конкретной редакции не заявляется:
`ratification_record=null`. Ни коммит, ни ИИ, ни зелёная сборка её не заменяют.
До принятия профиль описывает предлагаемое распределение функций; техническая
работа опирается на прямо порученные задачи и проверяемые контракты.

| Параметр | Локальная конкретизация |
| --- | --- |
| P01 Идентичность и область | Zhovten-Games/SPIDER, переносимые контракты и технический метод, пространства ID SP-/SP-OV-/SP-REG-. Профиль не распространяется автоматически на все продукты студии. |
| P02 Внешний порядок | MIT для кода, CC BY-SA 4.0 для адаптированных нормативных текстов, условия GitHub и применимые внешние обязательства. Неизвестный договор или юрисдикция права не выдумываются и не отменяются этим профилем. |
| P03 Источники намерений | Явное задание автора/уполномоченного владельца и задачи потребителей. При конфликте целей сохраняются варианты и последствия, решение передаётся затронутым людям. |
| P04 Официальный корпус | Точная универсальная редакция в `.code-constitution`, русский нормативный язык; Git, manifest и normative-translation связывают локальные источники и производные проверки. Локальные тексты пока candidate. |
| P05 Учредительные роли | Автор и заказчик задают намерение; ИИ — редактор и технический исполнитель по поручению. Ратификатор и удостоверяющий человек назначаются отдельной записью принятия; сейчас не назначены. |
| P06 Нормотворчество | Предложение имеет одну редакцию, область, diff и основания. Общие нормы принимает уполномоченный человек на срок мандата; текущий мандат инструмента ограничен задачей. Возражения и замещение публикуются; фиктивные независимые голоса не считаются. |
| P07 Исполнение | Назначенный разработчик выбирает средства внутри задания. Изменение межпроектного контракта согласуется с владельцами. Передача сохраняет pins/обязательства/дефекты; отзыв прекращает доступ в соответствующей области. |
| P08 Разрешение споров | Issue/PR с нормой, фактом и требуемым восстановлением; до учреждения инстанций спор передаётся владельцу, который раскрывает конфликт и при необходимости привлекает независимого человека. ИИ/CI не объявляются судьёй; окончательность и срок апелляции требуют записи принятия. |
| P09 Юрисдикции | SPIDER отвечает за общий технический метод; потребитель — за свой домен, стек и состояние. Это предлагаемая граница; репозиторий сам по себе не учреждает нормативную юрисдикцию. |
| P10 Первоначальная ратификация | `ratification_record=null`: ни состав единиц, ни согласия, ни кворум, ни момент силы не удостоверены. Перед принятием фиксируются носители, единицы/вес/порог/срок, отзыв и конфликт интересов конкретной замороженной редакции. |
| P11 Поправка | Автор или потребитель предлагает diff и план перехода; резервный путь — публичное обращение к владельцу при блокировании основной процедуры. Новая общая редакция и её согласия фиксируются отдельно; пороги и сроки следуют будущей записи принятия. |
| P12 Защищённые положения | Происхождение, человеческое полномочие, лицензия и чужое состояние не отменяются стековым override. Необратимое изменение, внешнее обязательство и пересечение проекта требуют явного согласия затронутых владельцев. |
| P13 Ресурсы и обязательства | Код/документы/pins — общие технические ресурсы. Задание разрешает обратимую подготовку; доступы, деньги, секреты, договоры и внешний выпуск не выводятся из него. Совместность устанавливается по затронутым владельцам. |
| P14 Аварийный порядок | Непосредственная угроза данным: минимальная остановка/откат до известной редакции, запись причины и результата. Режим длится до восстановления или человеческого пересмотра перед следующей поставкой; основной порядок им не меняется. |
| P15 Доказательства и реестры | Git хранит редакции и акты; manifests связывают источники, регуляторы и артефакты; отчёт задачи — результаты/ограничения. Отсутствующие назначения, голоса, договоры, исключения не подделываются. |
| P16 Техническое принуждение | SP-REG-BUILD-01 и SP-REG-PIN-01 ссылаются на точные правила/конфигурации. `make check` даёт ограниченное свидетельство; branch protection не заявляется установленной. Автоматический отказ воспроизводим и оспорим. |
| P17 Переход и восстановление | Bootstrap заменяет двухстрочный README проверяемой основой, сохраняет историю и старый commit для отката. Критерии: сборка, contracts, источник Конституции и явная граница готовности. Ратификация/назначения остаются отдельным переходом. |
| P18 Неписаный порядок | До публикации и доказательства повторяемой практики обычай не предполагается. Участники/область/свидетельства фиксируются в issue; высокорисковое неопубликованное ожидание не применяется неожиданно. Кодификация требует явного рассмотрения. |

Проверки и обычная реализация могут выполняться сейчас по заданию автора.
Принятие новых общих норм, лицензирование чужих материалов или назначение
независимых органов не выводятся из поручения написать код.
